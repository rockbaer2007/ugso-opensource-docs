# HA Grafik Visual Studio {#ha-grafik-visual-studio}

**Studio 0.1.296 :** Les **62 autres types de widgets** bénéficient désormais de propriétés multilingues (DE/EN/FR), de messages d'exécution, d'une fonction optionnelle de contrôle de la climatisation (Climate), ainsi que d'une vérification des sources, attributs et unités. Les projets et versions de paquets existants restent valides ; les nouveaux groupes sont créés à l'état désactivé. [Guide et limitations](/fr/projects/grafik-visual-studio/ha-quellen-climate). Le fonctionnement avec des appareils réels ou via l'application Companion n'a pas encore été confirmé par des tests en conditions réelles. [Rapport de test](https://github.com/rockbaer2007/ugso-ha-mqtt-addons/blob/master/ha_grafik_visual_studio/docs/remaining-widget-audit-2026-10-12.md).

À partir de la version **0.1.289**, l'indicateur **Enregistrer** change brièvement de couleur lors de l'opération : **orange** pendant le traitement de la requête, **vert** en cas de succès et **rouge** en cas d'erreur. La couleur normale est rétablie après 1,4 seconde. Ce comportement s'applique également à la sauvegarde automatique et fonctionne aussi bien en mode clair qu'en mode sombre.

Depuis **Studio 0.1.287**, tous les widgets disposent, dans l'onglet **WIDGET** (en haut), d'une case à cocher intitulée **Masquer à l'exécution** (*In Runtime verstecken*). Cette option permet de masquer le widget lors de l'exécution, indépendamment de son indice Z (*Z-index*) ; il reste toutefois modifiable dans l'éditeur. Les calculs et le flux de données demeurent actifs, même lorsque des widgets de type « Number » ou des « MathBox » sont masqués. Pensez à enregistrer le projet après avoir effectué cette modification.

Autres nouveautés depuis **Studio 0.1.285** : les éléments [SVG-Line](/fr/projects/grafik-visual-studio/svg-line) et les connexions de valeurs bénéficient désormais de positions de départ verticales, d'un tracé à angles droits (perpendiculaires) et d'une manipulation des points moins sensible. Les sorties des potentiomètres ([Poti-Ausgänge](/fr/projects/grafik-visual-studio/industrial)) contrôlent directement l'animation des lignes. L'exemple [Number→Math](/fr/projects/grafik-visual-studio/svg-linebox-math) illustre le flux net de la batterie (voir `O - P`) ; la [galerie](/fr/projects/grafik-visual-studio/bildergalerie) présente une image de l'éditeur avant la démonstration animée.

Nouveauté dans Studio **0.1.280** : le composant [Solar 0.1.3](/fr/projects/grafik-visual-studio/solar) propose sept points de connexion sur le bord inférieur de l'onduleur. Il intègre également quatre entrées pour panneaux solaires sur la partie supérieure (tête de pile), des connexions pour batterie au niveau de la jointure du boîtier, des couleurs distinctes pour les valeurs liées à la batterie, ainsi qu'un panneau solaire avec support, pouvant être inversé (effet miroir).

Nouveauté dans Studio **0.1.215** : Le [kit Material Design externe 1.0.0](/fr/projects/grafik-visual-studio/materialdesign) comprend **49 éléments (widgets)**, incluant des fonctions d'autocomplétion, des champs de saisie, des boutons, des affichages, des listes, des graphiques, des calendriers et des mises en page. Un projet comparatif permet de tester chaque widget individuellement.

Nouveauté dans Studio **0.1.214** : Le pack Material Design **0.3.0** intègre un [dialogue iFrame](/fr/projects/grafik-visual-studio/materialdesign) — le troisième widget de la série — doté d'une source, d'un environnement isolé (sandbox), d'options de défilement et de mises en page de dialogue compactes ou étendues.

Nouveauté dans Studio **0.1.210** : Le [kit Material Design externe](/fr/projects/grafik-visual-studio/materialdesign) est lancé avec des **aperçus de schémas de couleurs** (Preview Color Schemes), proposant 26 gammes de couleurs ainsi que des styles « Classique », « Material 3 » et « Standard du projet ». Le pack 0.1.0 est prêt pour le test d'enregistrement dans le catalogue de la communauté.

## Catalogue de packs et téléchargements {#paketkatalog-und-downloads}

Le pack **Météo et Chauffage (Wetter und Heizung) 1.7.1** affiche, pour sept widgets, les images d'aperçu originales issues de [ioBroker weather-and-heating](https://github.com/rg-engineering/ioBroker.vis-2-widgets-weather-and-heating). L'élément « Informer mon propriétaire » (« Meinen Vermieter informieren ») est désormais accompagné d'une icône en forme de lettre, car le fichier image référencé dans l'original est manquant. La licence MIT relative aux images originales est incluse dans le pack. Cette mise à jour concerne uniquement les images des widgets ; les paramètres existants restent inchangés. L'utilisation de Studio **0.1.216** (ou une version ultérieure) est requise pour effectuer cette mise à jour des images.

À partir de la page web du catalogue **0.1.11**, le paquet original téléversé lors de l'enregistrement est conservé de manière privée pour être examiné par l'administration. L'analyse et la validation s'appuient sur ce fichier sans nécessiter un nouveau téléversement ; toutefois, un nouveau fichier peut être téléversé en remplacement, si besoin. L'administration a la possibilité de télécharger l'original. L'empreinte SHA-256 permet de détecter toute modification. Cette copie privée est supprimée une fois le paquet validé, rejeté, supprimé ou après l'expiration de la période de conservation de 90 jours. Pour les soumissions plus anciennes, un nouveau téléversement unique est requis, car les versions précédentes se limitaient à l'analyse du fichier.

À partir de la page web du catalogue **0.1.10**, l'enregistrement de widgets accepte exclusivement le format `.wg`, tandis que l'enregistrement d'outils accepte exclusivement le format `.tp`. Le sélecteur de fichiers n'affiche que l'extension appropriée. Le serveur vérifie l'extension des noms de fichiers téléversés et des chemins des liens de téléchargement, ainsi que le contenu du paquet et le type de manifeste. Cette vérification lors du téléversement s'applique également aux opérations effectuées par l'administration.

Sur la page web du catalogue **0.1.9**, le formulaire d'enregistrement interroge sur l'utilisation de nouvelles fonctionnalités Studio (Oui/Non/Incertain). En cas de réponse « Oui » ou « Incertain », une description est requise et la version minimale peut être indiquée comme « Encore inconnue ». En cas de réponse « Non », la précision d'une version minimale est obligatoire. L'administration définit la version minimale lors de l'examen ou à la suite d'une adaptation nécessaire dans Studio ; une version précise doit être renseignée avant toute validation. Le téléversement facultatif d'un paquet permet de détecter les moteurs de rendu (renderers) ou les actions utilisés ; en l'absence de fichier, cette analyse est effectuée par l'administration. Les fonctionnalités inconnues se voient attribuer le statut « Adaptation Studio requise » et restent exclues du catalogue public jusqu'à leur mise en œuvre et un nouvel examen. La mise à jour de la page web doit être téléversée par l'exploitant.

À partir de la version Studio **0.1.212**, un symbole rouge **`mdi:alert`** signale la sélection via GitHub ainsi que les instructions d'installation pour les paquets de widgets et d'outils. L'utilisateur doit confirmer qu'il accepte les risques liés à l'installation avant de procéder.

À partir de la version Studio **0.1.213**, les mises à jour de paquets disponibles sont mises en évidence par un cadre vert autour de leur carte. Pour les nouveaux paquets compatibles, seul le bouton **Installer** apparaît en bleu. Une fois l'installation ou la mise à jour effectuée avec succès, ce marquage disparaît.

Studio détecte les nouvelles versions de paquets publiées lors de l'ouverture des paramètres des paquets ou via la fonction **Mettre à jour le catalogue**, et propose alors l'option **Mettre à jour**. Cette opération nécessite une correspondance entre les identifiants des paquets ; cela s'applique également aux paquets installés précédemment en local ou via GitHub. Les mises à jour sont installées de manière délibérée ; les dépôts GitHub ne font pas l'objet d'une surveillance automatique.

Vous trouverez des packs de widgets, des packs d'outils et des outils supplémentaires centralisés dans le [catalogue de packs UGSo, disponible sur visualstudio.ugso-software.de](https://visualstudio.ugso-software.de/?lang=de). Cela inclut des éléments liés à la technique, à la météo/au chauffage, un sélecteur de couleurs (Colorpicker), ainsi que les outils **Widget Test** et **Tools Test** permettant de vérifier l'installation des packs. L'outil **Packer** (pour Windows et Linux) est également disponible dans la section **Outils supplémentaires**. Les descriptions et les instructions sont hébergées sur ce site open source, tandis que les fichiers des packs sont proposés via le sous-domaine dédié au catalogue.

**Un tableau de bord pour Home Assistant qui sort de l'ordinaire.** « Grafik Visual Studio » est une application expérimentale pour Home Assistant, dotée d'un espace d'édition libre et d'un environnement d'exécution (runtime) séparé. Le projet en est à un stade précoce de développement ; son format et son fonctionnement sont susceptibles d'évoluer. Il n'est pas destiné, pour le moment, à être utilisé dans des tableaux de bord en environnement de production.

## Ce qui est actuellement possible {#was-derzeit-moglich-ist}

À partir de la version **0.1.222** du Studio, l'espace de travail s'affiche en gris dans le thème clair, avec des lignes de grille de couleur anthracite. Dans le thème sombre, l'arrière-plan habituel est conservé ; des lignes de grille légèrement plus claires facilitent le repérage. Cet affichage concerne l'éditeur. L'environnement d'exécution (Runtime) continue d'utiliser l'arrière-plan de page enregistré.

À partir de la version **0.1.221** du Studio, l'interface s'adapte automatiquement au paramètre clair/sombre indiqué par le navigateur. La barre d'outils, les barres latérales, les boîtes de dialogue et les champs de saisie changent d'apparence en temps réel, sans nécessiter de rechargement. Les arrière-plans de page et les couleurs des widgets enregistrés sont conservés ; le changement de thème n'altère aucun paramètre de projet enregistré.

À partir de la version **0.1.220** du Studio, l'ouverture d'une nouvelle page affiche directement l'onglet **VUE**. On y trouve les sections suivantes : CSS général, Arrière-plan, Police et texte, Options, Navigation, Barre d'application et paramètres responsifs. Ces sections peuvent être développées ou réduites, mais ne comportent pas de cases à cocher d'activation : les valeurs définies pour la page sont conservées lors de l'enregistrement. Les cases à cocher relatives à des options spécifiques, telles que « Standard », demeurent présentes.

À partir de la version Studio **0.1.218**, les commandes de commutation HA (Home Assistant) ayant échoué s'affichent sous forme de message rouge dans l'interface d'exécution (Runtime), indiquant l'ID de l'entité et la cause de l'erreur. À partir de la version **0.1.219**, un clic sur un commutateur verrouillé permet également d'en afficher la raison, par exemple un état HA manquant ou indisponible. Les widgets commutables permettent de piloter Home Assistant dans l'interface d'exécution ; dans l'éditeur, ils servent à prévisualiser le fonctionnement.

À partir de la version Studio **0.1.217**, la boîte de dialogue des entités permet d'effectuer des recherches parmi les noms d'affichage, les noms d'entités (personnalisés ou d'origine), les ID d'entités ainsi que les noms des appareils. Il est possible d'utiliser plusieurs termes de recherche répartis entre l'entité et l'appareil : par exemple, la requête **Licht Tv1** permet de trouver une entité nommée « Licht » associée à l'appareil « TV1 ». La recherche ne tient pas compte de la casse (majuscules/minuscules) ; les groupes d'appareils correspondants se développent automatiquement lors de la recherche.

- Dans la fenêtre des fichiers, le champ de recherche parcourt tous les sous-dossiers de `/config/www/studio`, indépendamment du dossier ouvert. La recherche ignore la casse et porte sur les noms de fichiers ainsi que sur les chemins. Les résultats affichent un aperçu de l’image et le chemin relatif ; les filtres de type de fichier et l’insertion d’images restent disponibles. Un champ de recherche vide affiche de nouveau le dossier ouvert.
- Il est possible de déplacer simultanément plusieurs widgets sélectionnés en faisant glisser l'un d'entre eux, y compris après une opération de copier-coller. Les lignes SVG et les points intermédiaires sélectionnés suivent le mouvement ; les connexions d'ancrage existantes sont préservées. Les widgets verrouillés empêchent le déplacement groupé. Une opération de déplacement peut être annulée dans son intégralité.
- La liste de sélection des widgets reste visible au premier plan, par-dessus tous les autres widgets. À partir de la version **0.1.209**, les widgets cochés sont gérés via les fonctions **Copier** et **Supprimer** situées dans la barre d'outils ; les boutons en double, auparavant présents en bas de la liste, sont supprimés. Une boîte de dialogue de confirmation s'affiche lors de toute suppression.
- Lors de la suppression de widgets, une boîte de dialogue de confirmation s'affiche, indiquant les identifiants (ID) des widgets sélectionnés. Les options « Annuler » ou la touche Échap permettent d'interrompre l'opération ; l'option « Ne plus demander pendant les 5 prochaines minutes » permet de masquer les demandes de confirmation pour toute suppression ultérieure durant les cinq minutes suivantes, dans l'éditeur ouvert. L'action de suppression reste annulable (fonction « Annuler »).
- La sélection de widgets — qu'il s'agisse d'éléments individuels ou de l'ensemble des widgets — est immédiatement répercutée dans la zone de l'éditeur. Pour les nouveaux widgets, les options « Images de signalisation », « Contrôle supplémentaire » et « Points d'ancrage » sont désactivées par défaut, mais peuvent être activées si nécessaire.
- La sélection d'images pour les widgets repose également sur le mécanisme **`/config/www/studio`** ; les chemins d'accès aux images repris ou copiés commencent par **`/local/studio/`**.
- Possibilité de gérer plusieurs projets ainsi que des pages nommées, chacune disposant de ses propres dimensions, de son propre arrière-plan et de ses propres widgets. L'environnement d'exécution (Runtime) affiche les pages visibles de manière distincte.
- Placez, déplacez, redimensionnez, nommez et organisez les widgets (via l'index Z) sur une surface accessible par défilement. L'éditeur propose des fonctionnalités telles que la sélection multiple, l'alignement, l'ajustement de la taille, le copier-coller, ainsi que les fonctions « annuler » et « rétablir ».
- Utilisez 74 widgets répartis dans les catégories « HA Grafik – Basis », « HA Grafik – Interaktiv », « HA Grafik – Spezial », « HA Grafik – Datenfluss » et « HA Grafik – Gauges ». Cela inclut des éléments HTML, des images, des affichages numériques, des commandes, des tableaux, des calendriers, l'intégration de tableaux de bord, des lignes SVG, des calculs, des convertisseurs et dix types d'instruments de mesure. La palette affiche un aperçu ou une icône selon le type de widget.
- Modifiez les propriétés relatives à la mise en page, au CSS, aux paramètres généraux, à la visibilité et aux points d'ancrage. Le filtre de widgets de l'éditeur utilise le champ « Mot-clé de filtre » (Filterwort) situé dans la section « Général ».
- Utilisez le widget spécial pour tracer des lignes de connexion dotées de points intermédiaires et de points de regroupement (activables explicitement), avec personnalisation des couleurs, des pointes de flèche et des animations. Les lignes qui se croisent ne se connectent pas automatiquement entre elles.
- Sélectionnez des fichiers depuis le dossier `/config/www/studio` de Home Assistant et importez des fichiers pris en charge. Le navigateur de fichiers crée automatiquement ce répertoire racine à l'ouverture ; si les droits d'écriture sont insuffisants, une notification vous invitera à le créer manuellement. Le navigateur d'entités permet de rechercher des entités ainsi que leurs états actuels, et d'intégrer les identifiants d'entité (Entity IDs) dans les champs des widgets.
- Enregistrez vos modifications automatiquement après un délai configurable (cinq secondes par défaut) ou effectuez une sauvegarde manuelle. Les widgets peuvent être exportés et importés au format JSON.
- L'interface adopte la langue configurée dans Home Assistant : l'allemand si HA est en allemand, l'anglais dans le cas contraire. Dans **Paramètres → Langue**, chaque navigateur peut être configuré sur **Automatique**, **Allemand** ou **Anglais**. Le contenu des projets et des widgets demeure inchangé.

## Extensions prévues {#geplante-erweiterungen}

À l'avenir, Grafik Visual Studio ne servira pas uniquement à la création de visualisations, mais aussi à leur distribution et à leur affichage de manière indépendante. Les points suivants constituent des objectifs de développement. Ils ne correspondent pas encore à des fonctionnalités pleinement disponibles ; leur périmètre et leur ordre de réalisation sont susceptibles d'évoluer en fonction des résultats des tests et des retours des utilisateurs. L'ensemble des fonctionnalités actuellement disponibles est présenté dans la section **Ce qui est possible actuellement**.

- **Exportation et importation de projets complets :** Sauvegarder, transférer et restaurer des projets — incluant les images nécessaires, les paramètres et les informations sur les paquets — sur une autre installation. Cette fonctionnalité d'exportation de « paquets de projet » viendra compléter l'exportation JSON existante, qui ne concerne que des widgets individuels.
- **Environnement d'exécution (Runtime) séparé sur un appareil dédié :** Exécuter des visualisations finalisées indépendamment de l'éditeur, par exemple sur un Raspberry Pi utilisé comme écran mural ou panneau de contrôle. La connexion à Home Assistant sera configurable. La vue « Runtime » existante servira de base ; un paquet « Runtime » autonome, destiné à des appareils distincts, constitue un objectif supplémentaire.
- **Application de couplage :** Une application complémentaire est prévue pour faciliter la configuration et l'établissement des connexions entre le Studio, le Runtime et Home Assistant. Le périmètre fonctionnel exact reste à définir.
- **Outil de création de paquets (Packer) avancé avec intégration GitHub :** Créer localement des paquets de widgets ou d'outils, avec la possibilité de créer un dépôt GitHub et d'y publier des versions du paquet. La création de paquets en local restera possible sans recours à GitHub. De plus amples informations sur l'outil existant sont disponibles sous [Packer pour les paquets](/fr/projects/grafik-visual-studio/packer).
- **Enregistrement direct des paquets depuis le « Packer » :** Soumettre des paquets au [Catalogue de la communauté](https://visualstudio.ugso-software.de/?lang=de) en fournissant les mêmes informations (licence, auteur, politique de confidentialité, compatibilité avec le Studio) que celles requises sur le site web. L'intégration au catalogue public reste soumise à une vérification préalable.

### Éléments devant faire l'objet d'une documentation {#was-dazu-dokumentiert-werden-soll}

- **Transférabilité :** Quelles ressources sont incluses dans une exportation, quels packs d'extension sont requis sur la cible et quelles connexions doivent y être configurées.
- **Identifiants :** Gestion des jetons (tokens) Home Assistant et des identifiants GitHub. Une exportation de projet standard ne doit contenir aucune donnée sensible (secrets) en clair.
- **Prérequis d'exécution (Runtime) :** Appareils pris en charge, configuration, connexion réseau et comportement en cas de perte de connexion.
- **Maintenance des paquets et compatibilité :** Gestion des versions, mises à jour et interaction entre le Studio, le Runtime et les packs d'extension.
- **Contribuer :** Recherche de testeurs et de développeurs ; canaux pour signaler des bugs ou faire des suggestions. Les problèmes peuvent être rapportés via les [GitHub Issues](https://github.com/rockbaer2007/ugso-ha-mqtt-addons/issues). Si vous avez découvert le projet via un message sur le forum, vous pouvez également contacter l'auteur par la messagerie privée du forum ; une expérience avec ioBroker VIS/VIS2 est un atout.

## En projet : Intégration JSON pour calendrier {#vorgemerkt-kalender-json-integration}

Une intégration dédiée pour Home Assistant est prévue ; elle fournira les calendriers HA sous forme de listes d'événements au format JSON, exploitables par des widgets de calendrier ou d'autres composants. Le nombre d'événements correspondra à l'état du capteur, tandis que la liste complète sera disponible dans l'attribut `events`. La période couverte et la fréquence de mise à jour seront configurables. Une connexion directe (`calendar.*`) au calendrier existe déjà, mais cette intégration réutilisable reste à implémenter.

## Limites de l'état actuel {#grenzen-des-aktuellen-stands}

Dans le Runtime, les éléments de type Sensor, String, Red Number, Bar, Gauge et Bool HTML interrogent l'entité Home Assistant associée toutes les cinq secondes ; les règles de visibilité s'appuient également sur ces états. Un widget de type « interrupteur » (switch) permet de commander `switch`, `light` et `input_boolean` via les services HA, et affiche ensuite l'état confirmé par HA. Les autres widgets de données et de contrôle utilisent encore des valeurs de test locales. La sélection d'un « Entity ID » (identifiant d'entité) ne correspond pas encore à une connexion en temps réel. L'option « Uniquement pour les groupes » (dans les paramètres de visibilité) ainsi que le comportement de `multi-views` ne sont pas encore totalement implémentés. Le filtre de l'éditeur ne s'applique qu'à la vue de l'éditeur.

L'application dispose d'une entrée standard « Home Assistant Ingress ». L'utilisation d'entrées distinctes dans la barre latérale pour l'éditeur et l'environnement d'exécution (runtime) nécessite l'intégration expérimentale issue de `custom_components/ha_grafik_visual_studio` ; celle-ci requiert Home Assistant OS ou une installation de type « Supervised » (avec Supervisor). Le fichier README du dépôt (https://github.com/rockbaer2007/ugso-ha-mqtt-addons/blob/master/ha_grafik_visual_studio/README.md) détaille les étapes d'installation.

L'interface utilisateur s'inspire de VIS2. « Grafik Visual Studio » est une implémentation indépendante ; le code et les widgets de VIS2 ne sont pas inclus.
